Next-Concept Modeling Primer

A language model usually writes one token for each network pass. NCM writes the full sequence as a stack of drafts. Each draft is longer and more exact than the draft before it. One network pass writes one full draft.

Sources, in order of authority: the paper (Kumbong, Khare et al., 9 Oct 2026) for claims and numbers; the released code ncm-main/ for inference mechanics; the Turing Post video "Attention Span" for analogies and critique, each time with attribution. A cited file:line refers to the copy in ncm-main/ of this page's repository, taken from HazyResearch/ncm (MIT license).

Stage 1: tokenizer. A multiscale residual VQ-VAE changes $L$ tokens into $K$ lists of discrete codes. List $k$ has $\ell_k$ codes, and $\ell_1 \lt \dots \lt \ell_K = L$.
Stage 2: generator. A transformer predicts list $k$ in one pass, all $\ell_k$ codes in parallel. Its input is the sum of the earlier lists.
Result. $K$ passes instead of $L$ (autoregressive) or $T$ full-length passes (diffusion). On LM1B, $K=12$, $L=128$.

0A picture to keep: the sheet stack

One example runs through this page. It is a mental picture, not model output. Think of a text as a drawing made on a stack of transparent sheets. The bottom sheet has one large tile. Each sheet above it has more, smaller tiles. Each sheet adds only what the sheets below it do not show. Look through the full stack and you see the finished text.

1The problem: how many passes, and how long is each pass

Let $L$ be the number of output tokens. Three schedules are in use.

  • Next-token prediction (NTP). $L$ sequential passes. Each pass adds one token. A key-value (KV) cache keeps the work of earlier passes.
  • Masked diffusion (for example MDLM). $T$ passes. Each pass processes all $L$ positions. The paper names three costs: many passes, full-length passes without AR-style KV-cache reuse, and large training budgets (MDLM and DUO used more than 500B training tokens on OpenWebText).
  • Next-concept modeling (NCM). $K$ passes, $K \ll L$. Pass $k$ processes only $\ell_k$ positions.

The Turing Post video gives this analogy: NTP is a typewriter, diffusion is an editor who fills blanks, and NCM is an architect who draws the outline first. The paper's own term is coarse-to-fine generation.

Sheet stack · stage 0

The three schedules are three ways to fill the top sheet of eight word tiles. Next-token prediction fills one tile for each pass. Diffusion works on all eight tiles in each pass. NCM does not start on the top sheet: it starts on the one-tile bottom sheet.

What "concept" means

The paper: "The term concept here refers to the information carried by the coarse levels of the hierarchy" (Section 3). A concept is not a word or a sentence vector. It is a code index at a coarse level.

3Stage 1: the multiscale residual tokenizer

3.1 Three ideas, each adds one thing

Vector quantization (VQ). Replace each latent vector with its nearest codebook entry (Eq. 1):

$$z_q^i=\arg\min_{e\in\mathcal V}\lVert z^i-e\rVert_2^2 .$$

The output is one integer for each position. One snap leaves an error.

Residual quantization. Quantize the error with a second codebook, then the new error with a third (Eq. 2). The reconstruction is a sum, $\hat z^{(K)}=\sum_k e_k(r_k)$. Each level corrects the levels before it.

Multiscale. Give early levels fewer positions. Level $k$ first shrinks the residual to $\ell_k$ vectors, snaps them, then stretches the result back to length $L$ (Eq. 7, 8):

$$u_k=\mathrm{Down}_k\big(z^{(k-1)}\big)\in\mathbb R^{\ell_k\times d},\qquad r_k^i=\arg\min_{j}\lVert u_k^i-e_{k,j}\rVert_2^2,$$ $$\hat z^{(k)}=\hat z^{(k-1)}+R_k\big(e_k(r_k)\big),\qquad z^{(k)}=z-\hat z^{(k)},\qquad \hat z^{(0)}=0 .$$

On LM1B, level 1 has $\ell_1=1$: one index from 8,192 entries, at most 13 bits for the full sequence. A learned resize stretches that one entry to a length-$L$ pattern (models/quant.py:406-407), so the level can select one of 8,192 sequence-wide patterns but cannot describe any single token. A level with $\ell_k=L$ can correct each token. That is the source of the coarse-to-fine order.

Sheet stack · stage 1

The equations above are the rule for making the sheets. Shrink the part of the picture that is still missing to the tile count of the sheet ($\mathrm{Down}_k$). Replace each tile with the nearest stamp from that sheet's stamp box (the codebook). Stretch the stamped sheet back to full size ($R_k$) and put it on the stack. What is still missing ($z^{(k)}$) goes to the next sheet.

3.2 The same loop in the released code

# condensed from MultiscaleResidualVectorQuantizer.z_to_idx, models/quant.py:573-609
z_rest, z_hat, idx = z.clone(), torch.zeros_like(z), []
for k, l_k in enumerate(levels):                  # e.g. [1, 8, 16, ..., 128]
    u = down(z_rest, l_k) if k != K - 1 else z_rest      # area pooling, L -> l_k
    r = torch.cdist(u, codebook[k].weight).argmin(-1)    # nearest entry (Eq. 7)
    q = codebook[k](r)
    q = up(q, L) if k != K - 1 else q                    # linear interp, l_k -> L
    q = phi[k](q)                                 # 0.5*q + 0.5*Conv1d(q)
    z_hat, z_rest = z_hat + q, z_rest - q         # Eq. 8
    idx.append(r)

Two facts from the code that the equations do not show. First, the encoder $E_\phi$ in the released configurations is an embedding lookup with zero transformer blocks (models/vqvae.py:41; Table 5 "Encoder blocks 0"). The encoder adds no contextual mixing. Positions mix only through the normalization before quantization, the resize operators and the small convolutions. Second, the codebooks update by exponential moving average of the vectors assigned to each entry, not by gradient (models/quant.py:497-498; Table 5 "Codebook EMA decay").

3.3 Nested dropout: why coarse levels carry meaning

Without a constraint, the tokenizer can put all information in level $K$, which has one code for each token. Then levels $1..K-1$ are noise and the generator has nothing useful to predict first. The paper uses nested dropout: during training, sample a cutoff $k$, keep only levels $1..k$, and make the decoder reconstruct the text from $\hat z^{(k)}$. In the code, one cutoff is drawn for each forward call, with a set probability (models/quant.py:457-462, :525-530). Table 5 gives that probability as 0.5; LM1B trains on the full and a cut hierarchy with weights 0.7 and 0.3. The loss of the paper (Eq. 9), at the sampled cutoff $k$ (the code differs; see Section 10.3):

$$\mathcal L_{\text{tok}}=-\frac1L\sum_{i=1}^{L}\log p_\psi\big(x^i\mid\hat z^{(k)}\big)+\beta\,\mathrm{MSE}\big(z,\mathrm{sg}[\hat z^{(k)}]\big)+\mathrm{MSE}\big(\mathrm{sg}[z],\hat z^{(k)}\big).$$
  • Term 1 is the reconstruction cross-entropy. It makes each truncated stack of levels $1..k$ decodable.
  • Term 2 is the commitment loss with weight $\beta$ (0.25 in the configs). It pulls the encoder output toward the codes. $\mathrm{sg}$ is stop-gradient.
  • Term 3 trains the parameters between the codes and $\hat z$. The codebook entries get no gradient (models/quant.py:300), and the quantizer input is a detached copy of $z$ (:451-453). So Term 3 moves the small convolution after each upsample, the learned level-1 upsample, and, through a straight-through copy at level 1 only (:503-505), the learned level-1 downsample. It does not move the encoder; Terms 1 and 2 do that.
  • The arg-min has no gradient. A straight-through estimator copies the decoder's gradient from $\hat z$ to $z$ (models/quant.py:531: z_hat = z + (z_hat - z).detach()).

4Stage 2: the next-concept transformer

4.1 The model

Freeze the tokenizer. The generator is a distribution over code hierarchies. It has two factorizations (Eq. 4, 5):

$$p_\theta(r_{1:K})=\prod_{k=1}^{K}p_\theta\big(r_k\mid\hat z^{(k-1)}\big),\qquad p_\theta\big(r_k\mid\hat z^{(k-1)}\big)=\prod_{i=1}^{\ell_k}p_\theta\big(r_k^i\mid\hat z^{(k-1)}\big).$$
  • Across levels: autoregressive. Level $k$ depends on levels $1..k-1$. The dependence goes only through the sum $\hat z^{(k-1)}$, which is a fixed function of $r_{1:k-1}$.
  • Inside a level: conditionally independent. Given $\hat z^{(k-1)}$, each code is sampled without knowledge of its neighbours' samples. This assumption permits one pass for each level. It is also the main modeling restriction (see Section 7).
# condensed from NextConceptTransformer.generate, models/next_concept.py:660-685

for k in range(K - 1):

The generator is a painter who makes a new stack. It looks through the stack so far, paints all tiles of the next sheet in one pass, and puts the sheet on the stack. After the last sheet, the decoder reads the words through the full stack. Fig. 5 shows the same process with a real model: 11 sheets for one translation.

4.2 Watch one sample form

Three observations. (1) The first levels fix the frame ("However, …"). (2) Middle levels contain repeated words: "remain remain remain". (3) Quality is not monotonic: BLEU is 51.7 after level 8 and 38.9 after level 9. A later level can change an earlier decision, because each level writes a correction to the full draft. On Sudoku, 16 of 81 cells are correct after level 1 and 64 after level 11; the last level corrects 17 cells.

5Attention: why training is one pass

For training, put the inputs of all levels in one sequence: [prefix, level-1 block, level-2 block, …, level-$K$ block]. How level 1 enters depends on the config (Section 10.3): in TinyStories and OWT, level 1 comes from a stored unigram table and the sequence starts at the level-2 block (models/next_concept.py:91); in LM1B, XSum and Sudoku, the level-1 block holds learned query vectors (:239-242); in WMT14, a head on the prefix predicts level 1.

Block $k$ holds $\hat z^{(k-1)}$ pooled to $\ell_k$ positions, computed from the ground-truth codes. An attention mask keeps the blocks apart. One forward pass then gives the logits for all levels, and the loss is cross-entropy against the true codes (teacher forcing).

NCM uses a block-diagonal mask: a position attends only to positions in its own level, in both directions, plus the prefix. Earlier blocks are not necessary, because the input of block $k$ already contains the sum of the earlier levels.

6Training the generator

6.1 Objective and level weights

The loss (Eq. 10) is a weighted cross-entropy over all codes. $\tilde z^{(k-1)}$ is the reconstruction built from corrupted input codes (Section 6.2):

$$\mathcal L_{\text{NCM}}=-\sum_{k=1}^{K}w_k\sum_{i=1}^{\ell_k}\log p_\theta\big(r_k^i\mid\tilde z^{(k-1)}\big),\qquad w_k=\frac{\ell_k^{-\alpha}}{\sum_{j=1}^{K}\ell_j^{1-\alpha}}.$$

Level $k$ has $\ell_k$ terms of weight $w_k$, so its share of the loss is proportional to $\ell_k^{1-\alpha}$. With $\alpha=0$ each code has equal weight and the long levels dominate. With $\alpha=1$ each level has equal weight.

6.2 Conditioning corruption

In training, the input of level $k$ comes from the true codes. In sampling, it comes from the model's own samples, which contain errors. All codes of a level are sampled in parallel, so more than one error can enter the draft in one step. This mismatch is exposure bias.

The paper's remedy: during training, replace a fraction of the input codes with codes drawn uniformly from the same codebook. The targets stay clean. The model then learns to predict the correct next level from a damaged draft. The replacement rate decreases linearly across levels. On TinyStories, Gen. PPL after 10k steps falls from about 49 with no corruption to about 19 at the selected recipe with mean rate 0.5; a mean rate of 0.75 is worse again (paper Fig. 13; values read from the plot).

The teacher smudges some tiles on the lower sheets during practice. The correct next sheet stays the target. The painter learns to paint the correct sheet over a stack that has errors.

6.3 Algorithm 1 in five lines

  1. Encode text $x$ to target codes $r_{1:K}$ with the frozen tokenizer.
  2. Replace some codes at random to get $\tilde r_{1:K}$.
  3. For each level, build $\tilde z^{(k-1)}$, pool it to $\ell_k$ positions and project it to the hidden width.
  4. Predict all levels in one forward pass with the block-diagonal mask.
  5. Compute $\mathcal L_{\text{NCM}}$ against the clean $r_{1:K}$ and update $\theta$.

For prompts (summarization, translation, Sudoku clues) the prompt tokens go through the tokenizer's embedding table and a projection, and they form the prefix. The repository contains evaluation code only. It has no training loop and no corruption code, so Sections 6.1 to 6.3 rest on the paper.

7What the model optimizes: an evidence lower bound

NCM is a latent-variable model. The latent is the code hierarchy $r_{1:K}$. The decoder gives a likelihood $p_\psi(x\mid r_{1:K})=\prod_{n=1}^{L}p_\psi(x^n\mid\hat z^{(K)}(r_{1:K}))$ and the generator gives a normalized prior $p_\theta(r_{1:K})$. The text likelihood sums over all hierarchies:

$$p_{\theta,\psi}(x)=\sum_{r_{1:K}}p_\psi(x\mid r_{1:K})\,p_\theta(r_{1:K}).$$
Proposition (Appendix A, Eq. 16 to 18)

Let $r^*_{1:K}(x)$ be the hierarchy that the tokenizer assigns to $x$, with nearest-neighbour ties broken by a fixed rule. Then

$$\log p_{\theta,\psi}(x)\;\ge\;\underbrace{\sum_{n=1}^{L}\log p_\psi\big(x^n\mid\hat z_*^{(K)}\big)}_{\text{reconstruction}}+\underbrace{\sum_{k=1}^{K}\sum_{i=1}^{\ell_k}\log p_\theta\big(r_k^{*i}\mid\hat z_*^{(k-1)}\big)}_{\text{generation}},$$

and the gap is exactly $-\log p_{\theta,\psi}\big(r^*_{1:K}\mid x\big)\ge0$.

Proof. A variational distribution $q(r_{1:K}\mid x)$ is any distribution over the latent that one selects to get a lower bound on $\log p(x)$. Use the point mass $q(r_{1:K}\mid x)=\mathbf 1\{r_{1:K}=r^*_{1:K}(x)\}$. Its entropy is zero, so the ELBO $\mathbb E_q[\log p_{\theta,\psi}(x,r_{1:K})-\log q]$ is $\log p_\psi(x\mid r^*_{1:K})+\log p_\theta(r^*_{1:K})$. The sum that defines $p_{\theta,\psi}(x)$ has only non-negative terms and contains the term for $r^*_{1:K}$, so the sum is at least that term. Substitute the two factorizations to get the right side. For the gap, $\log p(x)-\log p(x,r^*)=-\log p(r^*\mid x)$ by the definition of conditional probability. ∎

Reading.

  • With a frozen tokenizer, only the generation term depends on $\theta$. With clean inputs and $\alpha=0$, $\mathcal L_{\text{NCM}}$ is that term divided by $-N$, $N=\sum_k\ell_k$. Minimizing the loss maximizes the bound.
  • Corruption and $\alpha\ne0$ change the objective. Then it is not this ELBO.
  • The bound is tight only if the model's posterior puts probability one on the tokenizer's hierarchy. The paper does not report the size of the gap, and it reports no likelihood or perplexity of NCM on held-out text. Quality is measured by generative perplexity under another model.

Consequence of independence inside a level

Suppose that, given the draft, positions $i$ and $j$ must agree on one of two choices, each with probability 1/2. A factorized distribution gives each position 1/2 for each choice, so the two disagree in half of the samples. NCM must make such choices at a level where one code covers both positions, or correct the conflict at a later level. This is an interpretation, not a claim of the paper. It agrees with the repeated words in Fig. 5 and with the paper's statement that generations "exhibit occasional artifacts at coarse-level transitions" (Appendix I).

8Cost: a count of positions

This section is a derivation from the level schedules in ncm-main/config/eval/*.yaml. It is not a result of the paper. Assumptions: equal model size for the two methods; the feed-forward cost of a pass is proportional to the positions it processes; the attention cost is proportional to the square; prefix and tokenizer decoder are not counted.

$$\frac{\text{diffusion positions}}{\text{NCM positions}}=\frac{T\,L}{\sum_{k=1}^{K}\ell_k},\qquad\frac{\text{diffusion attention pairs}}{\text{NCM attention pairs}}=\frac{T\,L^2}{\sum_{k=1}^{K}\ell_k^2}.$$

For LM1B at $T=128$ the count gives 25.6 times fewer positions and 39.9 times fewer attention pairs. The paper measures 21 times less wall-clock time against DUO at 128 steps (1,024 sequences, batch size 16, one NVIDIA H100). A count is not a time: the measurement also contains the decoder pass, the sampler and GPU effects at short sequence lengths.

Against NTP the picture is different. NTP with a KV cache processes $L$ new positions in total, fewer than $\sum_k\ell_k$ (128 against 641 on LM1B). NCM's advantage over NTP can only come from fewer sequential passes (12 against 128). The paper has no wall-clock comparison against an autoregressive model with a KV cache (see Section 10).

9Evidence

Terms. BLEU scores a translation by its n-gram overlap with a reference; ROUGE-1, ROUGE-2 and ROUGE-L score a summary by unigram, bigram and longest-common-subsequence overlap. Higher is better for both. Classifier-free guidance (CFG) runs the model with and without the prompt and moves the logits away from the no-prompt result; it costs two passes for each level. Baselines: MDLM, DUO and E2D2 are discrete diffusion models; ELF, AURORA-LM, FLM and FMLM+ are continuous flow or diffusion models; AR is a next-token transformer of similar size.

Generator sizes differ by table: 97M on LM1B, 25M to 29M on Sudoku (Table 3), and 88M to 205M across the rows of Table 2 (NCM: 120M on WMT14, 88M on XSum). Each dataset has its own tokenizer and generator. Gen. PPL is the perplexity that GPT-2 large gives to the samples; lower is better, but repeated text also lowers it. H is the mean unigram entropy for each sample, a diversity check. A fair result has H near the value of real data.

9.4 Training budget and scaling

  • LM1B: tokenizer plus generator see 13.36B token positions (6.80B + 6.55B) against 66B for the baselines, a factor of 4.9. OWT: 127.22B against more than 500B, about a factor of 4. These count token exposure, not FLOPs.
  • The paper's suggested reason: one fixed coarse-to-fine order is simpler to learn than the many orders a diffusion model must learn. The paper calls this "one possible explanation".
  • Generators with 97M, 317M and 725M parameters on one frozen LM1B tokenizer: Gen. PPL falls as size increases at a fixed token budget (paper Fig. 6a). The paper calls these results preliminary.
  • More levels help with decreasing returns: on TinyStories, each doubling of $K$ from 4 to 32 lowers Gen. PPL by 52%, 32% and 20% (paper Fig. 9, no corruption, 10k steps).

10Limits and open questions

10.1 Stated by the paper (Appendix I)

  • Fixed shape. $K$ and each $\ell_k$ are fixed for a dataset, "so even short continuations traverse the full hierarchy". The paper proposes an input-dependent schedule as future work. The Turing Post video adds that NCM has no variable-length output; in the released models a shorter text fills the remaining positions with padding.
  • Two separate stages. The tokenizer is trained first and frozen. Representation learning is not aligned with the generative objective.
  • Scale. Main experiments use about 100M parameters; the scaling study stops at 725M on LM1B.
  • Artifacts. "Occasional artifacts at coarse-level transitions."

  • One model for each task. Correct: Appendix B states a separate tokenizer and generator for each of six datasets. The tokenizer adds parameters to the count (LM1B: 111.4M tokenizer beside the 97M generator).
  • The speed-ups are against diffusion and flow models. Correct. The paper's timing panels (paper Fig. 1a and 1b, the OWT panel of paper Fig. 5, and paper Fig. 6) contain no autoregressive curve, and the text gives no AR time. Table 2 gives AR quality at 64 NFE but no AR time.
  • Hardware claim. The video rejects the statement that NCM makes GPU memory unnecessary; its argument is that parallel prediction of a level increases arithmetic work for each weight load. The paper makes no hardware-market claim. This page does not examine that subject.

10.3 Paper against released code

Differences observed in this folder. No cause is assumed.

The pass counts below come from a reading of generate() and scripts/eval_shard.py. No model was run.

  • Evaluation only. The repository has no optimizer loop, no data pipeline, no generator loss and no corruption code. The tokenizer's training-mode forward pass, with the level cutoff, is present (models/quant.py:448-531).
  • First level. Algorithm 2 predicts all $K$ levels with the generator, starting from the resized zero draft. The released configs use four mechanisms:
    • tinystories.yaml, owt.yaml: query_level0: false, level0_unigram set. Level 1 is drawn from a stored unigram table (scripts/eval_shard.py:71, :156). The training sequence holds levels 2 to $K$ only (models/next_concept.py:91). generate() runs $K-1$ passes: 11 for TinyStories, 31 for OWT, against NFE 12 and 32 in the paper.
    • lm1b-*.yaml: query_level0: true and level0_unigram set. The model has a block of learned level-1 queries (models/next_concept.py:239-242), but scripts/eval_shard.py:156 supplies level 1 from the unigram table, so generate() runs 11 passes against NFE 12.
    • xsum.yaml, sudoku-*.yaml: query_level0: true, no unigram table. One pass on the learned queries makes level 1 (models/next_concept.py:581-626), then $K-1$ passes. Total 9 for the XSum config and 12 for Sudoku.
    • wmt14.yaml: predict_level0: true. A head on the prefix pass makes level 1 (models/next_concept.py:629-640), then 10 passes. Total 11, equal to the paper.
  • XSum levels. config/eval/xsum.yaml lists 9 levels (4, 6, 10, 14, 20, 26, 32, 40, 48) and generate() runs 9 passes. Table 5 gives $K=8$ and Table 2 gives NFE 8. The authors' animation in Fig. 2 also shows "level 1/9" for XSum.
  • OWT size. config/eval/owt.yaml has 16 blocks, width 1,024, 16 heads and codebooks of 8,192. Tables 5 and 6 give 12 blocks, width 768, 12 heads, 94.65M parameters and codebooks of 4,096.
  • Where the tokenizer loss is evaluated. Eq. 9 uses $\hat z^{(k)}$ at the sampled cutoff in all three terms. In models/quant.py:519-523, Terms 2 and 3 are added at every level and divided by $K$, before the cutoff is drawn (:525-530). Only the decoder input, and so Term 1, uses the cutoff.
  • Token selection. Algorithm 2 selects tokens by argmax. For LM1B and XSum, scripts/eval_shard.py:99-123 applies a frequency penalty and an adjacency penalty in a left-to-right loop over the decoder logits (LM1B: 11.5 and "10,4,0.5").
  • Guidance. models/next_concept.py:481-482 scales the guidance weight linearly with the level, from 0 at level 1 to the full value at level $K$.

12Self-check

1. On LM1B, how many codes does the generator predict for one sample, and how many passes does that take?

$\sum_k\ell_k=641$ codes in $K=12$ passes (the paper's count). An autoregressive model over the same codes would need 641 passes.

2. Why can the block-diagonal mask drop attention to earlier levels without losing all information about them?

The input of block $k$ is $\hat z^{(k-1)}$, the sum of the upsampled embeddings of levels $1..k-1$, pooled to $\ell_k$ positions. The earlier levels are in the input values. The pooling loses detail, so the summary is not complete.

3. Remove nested dropout. What do you expect from the generator?

The tokenizer is free to put most information in the fine levels. Coarse codes then say little about the text. The generator's early passes fix little, and the fine levels must be predicted from an uninformative draft with independent samples at each position.

4. Derive the share of the loss for level $k$ and give its value for level 12 of the TinyStories schedule at $\alpha=0$, levels 2 to 12.

Share $=w_k\ell_k/\sum_jw_j\ell_j=\ell_k^{1-\alpha}/\sum_j\ell_j^{1-\alpha}$. At $\alpha=0$: $128/640=20\%$.

5. A colleague says: "NCM is 21 times faster than LLMs." Correct the sentence.

The paper measures 21 times less wall-clock time than DUO, a diffusion language model, on LM1B at better generative perplexity, with models near 100M parameters. It gives no time comparison against an autoregressive model, and the autoregressive baselines in Table 8 have lower generative perplexity.

6. Why does corruption apply to the inputs and not to the targets?

The aim is to copy the sampling condition: the draft contains wrong codes, and the model must still predict the correct next level. Corrupted targets would teach the model to output wrong codes.
